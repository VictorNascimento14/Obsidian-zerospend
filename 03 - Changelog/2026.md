### ✨ Adicionado

- **Regras de cobrança** · 2026-09-29 · Frontend · PR #11 · [[2026-09-29-pr-011-regras-de-cobranca]]

  **Para o produto.** O ZeroSpend já sabe quanto cada assinatura custa por mês (a anual dividida por
  12), somar o gasto da empresa na moeda dela (convertendo o dólar pela cotação informada) e dizer a
  próxima data de cobrança, mesmo quando a data cadastrada já passou.

  **Para o time técnico.** `billing.ts` com `monthlyAmount`, `convertAmount`, `monthlyAmountIn`,
  `totalMonthlySpend` (sem as canceladas) e `nextChargeDate` (avança pelo dia-âncora); `addMonths`;
  `Organization` com `defaultCurrency` e `brlPerUsd`. Ver [[RegrasDeCobranca]].

- **Modelo de domínio e testes no CI** · 2026-09-29 · Frontend · PR #10 · [[2026-09-29-pr-010-dominio]]

  **Para o produto.** Ainda invisível: o ZeroSpend passa a ter o modelo de assinatura da especificação,
  as categorias de software e o formato brasileiro de dinheiro (R$ 8.450,00) e de data (05/10/2026).

  **Para o time técnico.** `src/lib/domain/` com tipos, lista fechada de categorias, `isIsoDate`,
  `toIsoDate`, `formatMoney` e `formatDate`. Vitest 5 com o fuso de São Paulo fixado (o CI roda em
  UTC), `npm test` e o passo de testes no CI. Ver [[ModeloDeDominio]] e
  [[2026-09-29-teste-de-data-precisa-do-fuso-do-brasil]].

- **Primitivo de tabela** · 2026-09-29 · Frontend · PR #9 · [[2026-09-29-pr-009-tabela]]

  **Para o produto.** A tabela que vai listar as assinaturas fica pronta, com rolagem lateral no
  celular.

  **Para o time técnico.** `Table` do shadcn (`base-nova`), sem alteração no arquivo gerado. Fecha a
  fundação de primitivos (ordens 1 a 7 do plano). Ver [[Primitivos]].

- **Primitivos de sobreposição e avisos** · 2026-09-29 · Frontend · PR #8 ·
  [[2026-09-29-pr-008-primitivos-sobreposicao]]

  **Para o produto.** Janelas de diálogo, confirmação de exclusão, menu de ações, painel lateral,
  dicas e avisos rápidos ficam prontos — em português, inclusive o que o leitor de tela lê.

  **Para o time técnico.** `Dialog`, `AlertDialog`, `DropdownMenu`, `Sheet`, `Tooltip` e `Toaster`
  (Sonner) do shadcn `base-nova`; `TooltipProvider` e `Toaster` no layout. "Close" virou "Fechar" nos
  arquivos gerados, e o toast herda a fonte do tema. `DropdownMenuLabel` fora de `DropdownMenuGroup`
  derruba a página. Ver [[Primitivos]].

- **Primitivos de formulário** · 2026-09-29 · Frontend · PR #7 · [[2026-09-29-pr-007-primitivos-formulario]]

  **Para o produto.** Campos de texto, seleção, área de texto, chave liga-desliga e caixa de marcação
  ficam prontos, com foco e erro visíveis, para os cadastros que vêm.

  **Para o time técnico.** `Input`, `Label`, `Select`, `Textarea`, `Switch` e `Checkbox` do shadcn
  (`base-nova`), sem alteração nos arquivos gerados. O `Select` do Base UI precisa de `items` para
  mostrar o rótulo. Ver [[Primitivos]].

- **Primitivos base** · 2026-09-29 · Frontend · PR #6 · [[2026-09-29-pr-006-primitivos-base]]

  **Para o produto.** Botões, etiquetas, cartões, avatar, divisória e o esqueleto de carregamento
  ficam prontos, no visual do kit, para as telas que vêm.

  **Para o time técnico.** `Button`, `Badge`, `Card`, `Avatar`, `Separator` e `Skeleton` do shadcn
  (`base-nova`), gerados pelo CLI 4.21. O `Card` ganhou `shadow-sm` no primitivo. Ver [[Primitivos]].

- **Tema do design system** · 2026-09-29 · Frontend · PR #3 · [[2026-09-29-pr-003-tema]]

  **Para o produto.** O app ganha a identidade visual do kit do Figma — as cores, a fonte Inter, os
  cantos e as sombras — e o modo escuro, que segue a preferência do sistema.

  **Para o time técnico.** shadcn/ui `base-nova` sobre Tailwind v4: só a paleta do kit (a padrão
  zerada), tokens semânticos mapeados para o kit nos dois modos, `text-h1`…`text-h4`, `next-themes` e
  `cn` configurado para os títulos. O `destructive` do claro virou `danger-shade-200` por contraste.
  Ver [[Tema]] e [[linguagem-visual]].

- **CI no PR** · 2026-09-29 · Infra · PR #2 · [[2026-09-29-pr-002-ci]]

  **Para o produto.** Toda mudança passa a ser conferida automaticamente antes de entrar: o código
  compila, segue o padrão do projeto e chega com a documentação linkada.

  **Para o time técnico.** GitHub Actions: `ci.yml` (lint, type-check e build em todo PR e push na
  `main`, Node 22, `npm ci` com cache) e `pr-documentacao.yml` (reprova o PR sem a seção
  `## 📓 Documentação` com link para o cofre). Ver [[runbook-ci]] e, sobre a queda da máquina no meio
  do PR, [[2026-09-29-queda-da-maquina-deixa-objeto-do-git-vazio]].

- **Projeto criado** · 2026-09-29 · Infra · PR #1 · [[2026-09-29-pr-001-scaffolding]]

  **Para o produto.** O ZeroSpend passa a existir como aplicação web — por enquanto uma página em
  branco, a base de tudo o que vem.

  **Para o time técnico.** Next.js 16 (App Router, `src/`) + React 19 + TypeScript estrito + Tailwind
  v4 + ESLint 9; scripts `lint` (sem aviso) e `type-check` (com `next typegen`). Ver
  [[runbook-rodar-local]].
