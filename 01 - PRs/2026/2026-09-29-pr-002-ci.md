# PR #2 — chore(ci): rodar lint, type-check e build e checar a documentação do PR

## 🎯 Contexto

Ordem 2 de [[2026-09-29-plano-da-v1-do-frontend]]. Até aqui, "passou" dependia de alguém rodar os
checks na própria máquina, e linkar o cofre em todo PR dependia de alguém lembrar. Os próximos PRs
da v1 passam por este portão antes do squash.

## 🔧 Mudanças

- `.github/workflows/ci.yml`: job `lint · type-check · build` em todo PR e em todo push na `main` —
  `actions/checkout@v7`, `actions/setup-node@v7` com Node 22 e cache do npm, `npm ci`, depois
  `lint`, `type-check` e `build`. Permissão `contents: read`, teto de 15 minutos.
- `.github/workflows/pr-documentacao.yml`: job `seção 📓 Documentação` — reprova o PR cujo corpo não
  tenha o título `## 📓 Documentação` ou cuja seção não tenha ao menos um link para
  `github.com/VictorNascimento14/Obsidian-zerospend`. Roda em `opened`, `edited`, `reopened` e
  `synchronize`: corrigir o corpo do PR já dispara a checagem de novo.

## 🕵️ Dado sensível (LGPD e sigilo)

Nenhum. O corpo do PR entra no script por variável de ambiente e só é comparado com dois textos fixos.

## 🧠 Decisões técnicas

- O corpo do PR entra por `env:` (`CORPO`), nunca por `${{ }}` dentro do `run:` — expressão
  interpolada no script vira injeção de comando para quem escreve o corpo.
- O link é procurado **dentro** da seção (do título até o próximo `## `), não no corpo inteiro: é o
  que o `CLAUDE.md` do repositório promete.
- O `\r` sai antes da comparação: corpo editado pela interface do GitHub chega com `\r\n`.
- Concorrência: no PR, push novo cancela a rodada anterior; na `main`, nenhuma rodada é cancelada —
  cada commit da `main` fica com o seu resultado.
- Actions oficiais (`actions/*`) pela tag maior `v7`; action de terceiro, se um dia entrar, vai
  fixada por SHA.
- Node 22 no CI, o mesmo da máquina de desenvolvimento (o mínimo do Next 16 é 20.9).
- Testes (Vitest) ficam de fora: ainda não há o que testar. Entram na ordem 8 (`feat/dominio`).

## ⚠️ Armadilhas e aprendizados

- A máquina reiniciou no meio deste PR e deixou arquivos com 0 bytes, inclusive objetos do `.git`, e
  o git não regrava um objeto que já existe, mesmo vazio. Ver
  [[2026-09-29-queda-da-maquina-deixa-objeto-do-git-vazio]].
- A primeira simulação local da checagem imprimia o código de saída do `tail`, não o do script, e
  parecia passar em todos os casos. Simulação de script se mede pelo código de saída do próprio
  script.

## 🧪 Como testar

- O próprio PR roda os dois workflows.
- A checagem de documentação foi simulada localmente (`bash -e`) com seis corpos: passam o válido, o
  com `\r\n` e o sem quebra de linha no fim; reprovam o sem a seção, o com link só fora da seção e o
  vazio — cada um com a mensagem certa.

## 🚫 O que não foi verificado

- Sem `actionlint` na máquina: a sintaxe dos workflows foi conferida pelo parser YAML e pela primeira
  rodada no GitHub, neste PR.
- A proteção da branch `main` (exigir os checks para mergear) não foi configurada: hoje o portão é o
  fluxo de publicação, que só faz o squash com o CI verde.
