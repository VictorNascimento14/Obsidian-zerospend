# PR #40 — docs(readme): como rodar, conta de demonstração e mapa do app

## 🎯 Contexto

Ordem 38, a última de [[2026-09-29-plano-da-v1-do-frontend]]. O README era um esboço do começo do
projeto, com o que o produto é e onde fica a documentação. Com a v1 do front-end completa, quem chega ao
repositório precisa saber rodar, entrar e achar cada tela.

## 🔧 Mudanças

- **`README.md`:**
  - como rodar (Node 22, `npm ci`, `npm run dev`) e as quatro checagens do CI;
  - a conta de demonstração (`admin@zerospend.app` / `demonstracao`), as duas empresas fictícias e o
    extrato de exemplo;
  - o mapa das rotas e do header;
  - o que é de verdade, o que é demonstração e o que ainda não existe;
  - a stack e a estrutura de pastas.
- **Cofre, no fechamento do plano:**
  - [[2026-09-29-plano-da-v1-do-frontend]] ganha o mapa real ordem → PR, o status "concluído" e os
    desvios;
  - o "Implementado em" de [[ADR-001-frontend-primeiro-com-dados-locais]] e
    [[ADR-002-design-system-do-figma-com-shadcn]] fica completo, sem os "TODO".

## 🕵️ Dado sensível (LGPD e sigilo)

O README só cita os dados fictícios estáveis: a conta de demonstração (senha pública, "demonstracao") e
as empresas Exemplo Tecnologia Ltda e Clínica Exemplo.

## 🧠 Decisões técnicas

- **Cada afirmação do README foi conferida no código:**
  - PBKDF2 com sal em `password.ts`;
  - a semente na primeira leitura;
  - `--max-warnings=0` no lint;
  - o fuso de São Paulo no Vitest;
  - os 30 fornecedores do catálogo.
- **"De verdade × demonstração × ainda não existe"** em seção própria. É a regra "texto que afirma um
  efeito precisa do código que o produz" aplicada à porta de entrada do repositório.

## ⚠️ Armadilhas e aprendizados

- Nenhuma.

## 🧪 Como testar

Seguir o README numa cópia limpa: `npm ci`, `npm run dev`, entrar na conta de demonstração e percorrer o
mapa das rotas. O CI roda lint, type-check, testes (169) e build.
