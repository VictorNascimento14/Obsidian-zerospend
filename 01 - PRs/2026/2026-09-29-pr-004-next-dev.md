# PR #4 — chore(next): impedir o next dev de reescrever o arquivo de instruções

## 🎯 Contexto

Fora da ordem de [[2026-09-29-plano-da-v1-do-frontend]]: apareceu no [[2026-09-29-pr-003-tema]]. Ao
subir o `next dev` para conferir o tema, o Next 16.3 anexou um bloco gerado ao `CLAUDE.md` do
repositório. As regras do repositório são escritas à mão ali, e cada `npm run dev` deixaria o
`git status` sujo com um bloco que ninguém pediu.

## 🔧 Mudanças

- `next.config.ts`: `agentRules: false`, com o porquê no comentário.

## 🕵️ Dado sensível (LGPD e sigilo)

Nenhum.

## 🧠 Decisões técnicas

- Desligar em vez de commitar o bloco: o [[2026-09-29-pr-001-scaffolding]] já tinha deixado de fora os
  arquivos de regras do Next (`--no-agents-md`), pelo mesmo motivo — as regras do projeto moram num
  arquivo só, escrito à mão.
- PR próprio, e não dentro do tema: é outro assunto, e o pedido é um PR por peça.

## ⚠️ Armadilhas e aprendizados

- O Next só gera o bloco quando **detecta um agente de código rodando**. Quem sobe o `npm run dev` à
  mão nunca vê isso acontecer, e por isso a configuração parece sem motivo. O código está em
  `node_modules/next/dist/server/lib/start-server.js` (`initResult.agentRules !== false`), e a opção é
  documentada em `config-shared.d.ts`.

## 🧪 Como testar

1. `npm run dev` e abra `http://localhost:3000`.
2. `git status` continua limpo. Conferido: com a opção, o servidor sobe, serve a página e o arquivo de
   instruções não muda; sem ela, o log do `next dev` avisa que gerou o arquivo.

## 🚫 O que não foi verificado

Nada além disso — a opção só afeta o `next dev`.
